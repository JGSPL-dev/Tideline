# YourFeed (by Apps For Us), formerly tick/rss and Tideline

"Everything you follow, in one feed." One feed for websites, YouTube, Reddit, podcasts, Google News topics, Bluesky and Mastodon. No account, no tracking; data stays on the device. Do not promise "no ads" anywhere (decided 7 Nov 2026: ads may be part of the business model).

Brand: one orange, #d9480f (`--brand-fill`), for every solid fill in every theme: logo tile, wordmark "Feed", app icon, badges, counts, buttons. `--brand` (#ff8a4c in dark mode) is only for small orange text/lines that must stay readable on dark backgrounds. Android's status/navigation bars take the page background (`YFNative.setBars`), never orange. Wordmark in Bricolage Grotesque 800. Icon: Feed Check (two lines and a tick on an orange rounded square).

Everything lives in `index.html`, served by GitHub Pages at https://jgspl-dev.github.io/Tideline/ now at https://yourfeed.appsforus.co.uk (CNAME file; DNS-only CNAME yourfeed → jgspl-dev.github.io on Cloudflare). The same file is the Android app (`app/`, Capacitor 7, app ID `uk.co.appsforus.yourfeed`).

## Privacy and security rules (agreed Nov 2026)
- Only two kinds of network route: the publisher itself (direct from the device) and our own **YourFeed service** (`service/worker.js`). Never add third-party relays, readers or feed services (removed: allorigins, codetabs, whateverorigin, corsproxy.io, cors.lol, rss2json, Feedly, Jina).
- The service never relays web pages: feeds (validated), allowlisted JSON APIs, or extracted facts only. Sandbox CSP + nosniff on every reply, 5 MB cap, public-address check, CORS limited to our origins, per-IP limits. Its address: `SERVICE_DEFAULT` in index.html (empty until deployed) or Settings → YourFeed service (`yf.service`).
- The service keeps a shared store: edge cache per location plus KV (`YF_CACHE`, namespace yourfeed-cache) for YouTube API results (30 min fresh, written only on change or every 6 h, served stale if the API fails), channel lookups (30 days), searches (1 day), found feeds (7 days). The app asks the service first for YouTube lookups, search and videos (route `ytapi`, then the phone reads YouTube's feed, uploads feed, Videos page). YouTube WebSub push: `ensurePush` subscribes a channel at pubsubhubbub.appspot.com only once the API has confirmed it exists (first successful answer, or a shared copy exists); the per-channel secret comes from the `WEBSUB_SECRET` secret (older subscriptions signed with the YT_API_KEY-derived one are accepted until they renew). `/websub/youtube` GET confirms only a subscription we asked for in the last day (`push:<id>.asked`; unsubscribe never confirmed; rate limited), POST takes only deliveries whose HMAC matches (`sameText`, constant time); while pushing, API freshness is 6 h. Unknown channel IDs are remembered as misses at the edge (`ytmiss:`), so they cost one API unit, no KV write and no subscription. Discovery is remembered by origin + path (`disc:`), never for an address that is already a feed. Worker secrets: `YT_API_KEY`, `WEBSUB_SECRET`, `ADMIN_KEY`; optional `LIMITER` rate-limit binding (`overLimit`, on top of the per-instance count; IPv6 counted per /64 via `ipKey`). Error replies don't echo internal messages. `http://localhost:8765` is no longer an allowed origin.
- In the app, feeds are fetched with If-None-Match / If-Modified-Since (`feed.http` per URL); 304 = unchanged. Not until one full read has picked up the feed's artwork (`iconParsed`).
- The app fetches directly (`IS_APP`, CapacitorHttp) and only falls back to the service. The website needs the service for most feeds.
- No third-party loads at startup: fonts self-hosted in `fonts/`, no CDN scripts.
- Android release builds are signed with the private key in Actions secrets `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASSWORD` (alias `yourfeed`). Never commit a keystore. HTTPS only (no cleartext), WebView debugging off.
- Saved posts, folders and sources are local only; export/import via OPML (Settings → Sources). In the app, Export saves straight into the phone's Download folder (`deliverFile(..., {save: true})`: Filesystem `writeFile` to `EXTERNAL_STORAGE` `Download/yourfeed-sources-YYYY-MM-DD-HHMM.opml`; no permission needed on Android 11+), with a "Share it instead" link; if saving fails it falls back to the share sheet. Source health's Save as file does the same. The website downloads the file as usual.
- Private (paid) feeds: Patreon, Supercast, Substack etc. give a personal link with an access code. `isPrivateUrl` spots them: user:pass@; a parameter whose name says it's a key (`secretName`: token, auth, key, sig, pass, uid, user, session…, not "keyword"); a random-looking code (`randomCode`: a UUID, or 20+ letters and digits with no word breaks) in any parameter value or path segment on any host; /private/; Patreon /rss/; shorter codes on paid-podcast hosts (`PRIVATE_HOSTS`). Hosts whose codes are public IDs (`PUBLIC_CODES`: Google News, YouTube, Reddit, Bluesky) and `/public/` paths are exempt. No directory entry matches. `f.private` is set when added, and the edit form has a **Private feed** switch (locked on when the link itself looks private); `viaService` refuses private-looking addresses and any address of a source marked private. The service applies the same rules (`looksPrivate`) and refuses `/feed` and `/discover` for them (403), and only uses Cloudflare's shared cache for addresses without a query string. They are fetched only straight from the device: `viaService` refuses any private address, `loadOneFeed` skips the service route, no `healFeed`, added exactly as pasted (no lookups). On the website they show "Private: updates in the YourFeed app" and never count as trouble. Links are blanked with `redactUrl` in Source health and its shared report; export leaves them out unless "Include private feeds" is ticked; Share never sends a private episode's audio link. Padlock (`lockEl`) in the menu and Source health.

## How it works
- Fetch layer: `feedDirect`, `feedViaService`, `fetchFeedText`, `getJSON` (direct then service `/json`), `pageDirect` (app only), `discoverFeed`, `findChannel`. `loadOneFeed` records each route's answer in `feed.routes` (shown in the source's edit form with Check now). Reddit: in the app, one `/new/.rss` request from the phone, spaced 1.1 s apart, browser user agent.
- Each feed has its own schedule (`everyMin`, `nextCheck`, `isDue`): feed ttl / sy:update hints, else 15 min (podcasts 60), clamped 10 min–6 h; failures back off 5→60 min.
- Duplicates: within a feed, a story that comes back under a new address with the same headline keeps its first id only when it is a Google News item (it re-wraps links) or the two are within 20 hours (`sameStory`), so a daily "Morning briefing" is a new story each day. `storyKey` = headline (letters/digits, 20+ chars, not audio/video), with the " - Publisher" tail stripped only for Google News items (`isGNItem`). A story's date never moves later (live blogs don't jump back to the top) in `mergeHistory`. Across feeds, duplicates (same `linkKey` or `storyKey`, publisher's own feed preferred over Google News, then first seen) are worked out within what is shown after the source/date/seen filters (`baseItems` → `dupeIds(shown, key)`, memoised), so a story never vanishes from a folder because its copy lives in another; not applied when viewing one feed. `refreshAll` wraps `refreshAllInner` in try/finally so Refresh can never stay stuck.
- Seen, not read: a card counts as seen once it is ≥60% on screen (or fills half the screen) for 2 s (`lookObs` IntersectionObserver, `watchLook` in `cardEl`, `markLooked`, `state.looked` / `yf.looked`, last 6000; not in Saved). "New" counts = not seen and not tapped (`isNew`); one-off migration `yf.lookedMig2` starts seen from the tapped (read) set only (the first migration, which marked everything older than the last refresh as seen, made Hide seen empty the feed). Hide seen filters against `state.lookSnap`, re-taken only on filter/source change (`setView`, `selectFeed`), Refresh, or returning after 10+ min, so cards never vanish while scrolling. Tapped = read (faded card, `tl.read`) is kept separately.
- Podcast episodes without their own picture use the show artwork (`f.icon`) on cards, mini player and lock screen.
- News sitemaps: a site with no feed is read from its news sitemap (`isNewsSitemap`, `parseFeed` `urlset` branch: `<loc>`, `news:title`/`news:publication_date`, `image:loc`, title from the URL slug if needed). `#only=/path/` on the address keeps one section (fragment never sent). `findNewsSitemap(origin)` (app only, straight from the site): robots.txt `Sitemap:` lines with news/google, then `NEWS_SITEMAP_GUESSES`; a sitemap index → its newest news child. `discoverFeed` tries it after RSS. The service accepts news sitemaps as feeds (worker `looksLikeFeed`). Settings → Service → Find news sitemaps (`#smCheck`) reports which Google-News-routed directory sites have one, to switch them over (fewer calls to Google, real links and pictures). Nov 2026 run: 56 sites switched (e.g. Bloomberg, The Times, CNN, The Athletic `#only=/athletic/`, Autocar, Top Gear, Yahoo Finance); sources a person already added through Google News move to the new route automatically when their name matches a non-Google directory entry.
- Google News topics (not `site:` feeds) keep English headlines only (`looksEnglish` in `parseFeed`: other scripts out; Latin-script headlines judged by everyday words, `EN_WORDS` vs `OTHER_WORDS`, plus accent share). All Google News addresses already use the English editions (UK, or US for Worldwide).
- Crash guard: `fetchFeedNow` records sources being loaded in `yf.inflight` (only while the app is on screen). If the app dies mid-load, `crashCheck()` at start counts a crash against each (`f.crashes`); a source loading during two crashes gets `f.crashPaused` (skipped by `isDue`, plain message, "Check" in Source health unpauses). After a crash, the suspects (`f.crashes > 0`) are loaded first, one at a time, so only the real culprit is paused. Every text download goes through `readCapped` (refused when Content-Length is over the limit, cut off while reading otherwise): pages 3 MB (`MAX_PAGE`); gzip responses are refused. Feeds over 8 MB (`MAX_FEED`; long-running podcasts list every episode ever, e.g. The Football Ramble on Acast) aren't refused: the first 8 MB is kept and closed off at the last whole entry (`readCapped` `partial`, `wholeFeed`), the source is marked `f.big` and later asked for with `Range: bytes=0-7999999`; only over 40 MB (`HARD_FEED`) is refused. The service does the same within its 5 MB cap (`fetchCapped` `partial`, worker `wholeFeed`). News sitemaps (`f.sitemap`, set by `parseFeed`) are asked for with `Range: bytes=0-2999999` and repaired to whole entries (`wholeSitemap`). `parseFeed` picks the newest 80 entries by date before processing them (`newestOf`, `KEEP_PARSE`), so oldest-first sitemaps and 300-episode podcasts cost little. **Android:** `MainActivity` adds a `WebViewListener` whose `onRenderProcessGone` returns true and recreates the activity (Capacitor's default lets the app close), logging "YourFeed" in logcat and leaving a note the page reads once via `YFNative.takeRestart()` (toast + `yf.errlog`). (All added after 0.2.40 crashed a few seconds after opening.)
- Reddit ends RSS on 13 Nov 2026 (`REDDIT_END`): after that, once Reddit sources fail (2, or all if fewer), `yf.redditGone` pauses every Reddit source (`isDue`, not `isTroubled`), the status pop-up says so once, Source health shows one Reddit box (Try again `redditRetry` / Remove Reddit sources), and Reddit search returns nothing. - Trending in your feeds (Nov 2026; worked out on the phone, nothing sent): `trendTopics()` (memoised 10 min) reads headlines from the last 48 h (`TREND_HOURS`; Google News " - Publisher" tails and "WATCH:"-style prefixes removed) and takes names and subjects (`trendTokens`): capitalised words seen mid-headline somewhere, acronyms, and pairs of side-by-side capitalised words, which may include an everyday word ("Black Friday", "Premier League", "Storm Claudia") but not two ("Best Deals"; in title-case headlines one of the two must be a name seen elsewhere). `TREND_STOP` + `EN_WORDS` drop generic single words; a term in the source's own name doesn't count. A term trends when 3 different publishers mention it (2 for people with fewer than 15), counted by `trendPub` (a site's section feeds = one publisher; each channel, account, podcast or topic on its own). Terms sharing half their stories merge into one topic (max 12); a pair labels the topic over its single words ("Black Friday", never "Black"), which still bring their stories when most of theirs are the pair's ("Reeves faces revolt" joins Rachel Reeves; "Black Ops 7" stays out). - Full screen (app): MainActivity turns to landscape unless the video is a Short (`YFNative.setRotateFull(false)`), wraps the player in `DragToClose` (drag down to close), and calls `yfVideoEnter`/`yfVideoExit` in the page, which pauses the video (YouTube iframe API, `enablejsapi=1`) and scrolls the card back to where it was. The website does the same on `fullscreenchange`.
- Videos tab has a Videos | Shorts switch (`view.vkind`, `videoSwitch`; Shorts = `isShortItem`: `short === true` only, set by YouTube's /shorts/ links or the service's `shortCheck`, never by length) and Shorts show as a two-column grid of upright tiles (`.shortgrid`, stacks off). Settings → Hide YouTube Shorts (`yf.hideShorts`) removes them everywhere.
- One thing plays at a time: YouTube players are watched (`watchVideo`, iframe API "listening" + onStateChange); a video starting pauses the podcast and other videos, a podcast starting pauses all videos (`pauseAllVideos`), and in-feed videos pause when scrolled mostly out of view (`vidSeen` IntersectionObserver).
- No background play for YouTube: YouTube's API rules forbid it. Podcasts keep background play.
- Onboarding: welcome screen when there are no sources, interest picker → folders (`INTERESTS`), spotlight tour (`TOUR`).
- Categories: a fixed list (`INTERESTS`, 26; Literature & Arts added Nov 2026). A `DIRECTORY` feed is filed by its first tag (`tagCategory`, `TAG_CAT` aliases like games→Gaming, f1→Motorsport), so keep the first tag of every directory entry a category word. Broad ones (`BROAD`: Sport, Lifestyle, Business) count for less and give way to a clear match in their `FAMILY` (Sky Sports Golf → Golf). `categorise` scores the source's name/address (strong, 4), our directory tags (+3, so "The Guardian – Cricket" lands in Cricket; "guardian" is no longer a News word) and its recent posts (weak); new sources go straight into the winning category (folder made if needed) with an "Added to X · Change" note (cleared when the menu closes), no question. Sources with no folder are sorted on their first successful check (`autoCat`); a folder picked by hand (`folderSet`) is never changed.
- "Quiet" (`attentionList`, `rhythm`): websites after 3× their usual gap (min 3 days); podcasts after the longest of 30 days, 4× their usual gap, or 1.5× the longest break in their last 20 episodes (so season breaks seen before don't warn). "Usual" is the three-quarter mark of recent gaps, so bonus episodes don't make a weekly show look daily. The message says the rhythm: "Nothing new for 40 days (usually weekly)" (`rhythmWords`). Never applies to YouTube channels that load: they count as working.
- Needs attention lives in Settings under Source health (`renderAttention`, a collapsible bar; tapping a warning in the status line opens it). Rows: icon buttons Check / Remove (tap twice) / Dismiss (`f.dismissed`, cleared when the source works again; the status count stays honest).
- Podcasts: shared player `pod`, mini player, Media Session; in the app a forked media-session plugin (`app/plugins/media-session`) runs a foreground service, with back/forward as Android 13+ system media controls. Stall guard `checkPod`.
- YouTube is touchy about bursts from one connection (it blocks it with 404/500 for hours): requests go one at a time 1.5 s apart (app fetch wrapper), channels are checked every 30 min with a per-source jitter, at most 10 per refresh round, and `ytRefused`/`ytCooling` pause all YouTube requests 30 min→6 h after 4 refusals in a row. Fallbacks (uploads-playlist feed, channel Videos page) only for one-off failures. Imports by name look up one channel at a time.
- Android back button (`goBack`): closes the open layer, then returns to Everything, then minimises the app.
- Storage keys keep the old `tl.` prefix (new ones use `yf.`); keep them.
- **Start-up safety.** A small separate script before the app script (`window.__yfBoot`) catches errors: one while the app script is starting, a failure it reports (`boot.fail`), or a start not finished after 20 s shows a rescue screen (`#bootFail`: Try again; Clear saved stories and try again; Save my sources as OPML, private links included and labelled; Copy error details). The app calls `boot.finish()` once stories are drawn. All other errors go to `yf.errlog` (last 20; `logError`). Start-up steps run through `safely(...)`, so one failing step is logged and skipped. **One-off data changes go in `MIGRATIONS`** (numbered, run once each in order, each in its own try/catch; `yf.migrated` holds the last number done; the middle value is the older yes/no flag early ones used). Never renumber or remove a migration. Strict mode is on for the whole app script.
- Stories live in IndexedDB (DB `yourfeed`, store `kv`, record `items`; `itemsDB`), not localStorage, so a busy feed list can't hit the 5 MB limit. `itemsReady` loads them at start (moving an old `tl.items` copy across once, then deleting it); the list is drawn and `refreshAll` runs only after it resolves, and `saveItems` (at most one write per 0.4 s, always of the latest list; written at once when the app goes to the background) never writes before the load. Summaries are cut to 500 characters. A failed save shows one toast (stories, or settings via `store.set`, which now returns false on failure). Full article text is in the separate `tickrss` DB. Tests that read `localStorage['tl.items']` are obsolete: read IndexedDB instead (t126).

4. Links that push visitors to an app.

## Testing
- The sandbox can't reach outside sites: test with Playwright against mocked routes (direct publisher URLs with CORS headers, or a mocked service). `service/worker.js` can be unit-tested in Node with a stubbed `fetch`.
- **Every push runs `.github/workflows/checks.yml`** (`tests/`): `smoke.mjs` opens index.html offline, as the website and as the app, with saved data from different eras (first run; a pre-November 2026 install with stories in localStorage and no migrations run; 300 sources and 3,000 stories), and fails on any page error, the rescue screen, a start that doesn't finish, missing stories, or stories not coming back after reopening. `worker.test.mjs` (node --test) checks the service: origins, GET only, private/odd addresses refused without a request, web pages never relayed, JSON allowlist, community list rules (no IPs stored), rate limit. Run locally: `cd tests && node smoke.mjs && node --test worker.test.mjs` (`PAGE=file:///… node smoke.mjs` tests another copy). Add a saved state to `STATES` whenever a change touches stored data.
- Android builds run in GitHub Actions (`.github/workflows/android.yml`) and publish the `test-build` release (`yourfeed.apk`). Settings shows the build number. Builds are manual only (workflow_dispatch): do not trigger one until Josh asks; batch small changes into one release.
