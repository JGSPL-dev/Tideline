# YourFeed (by Apps For Us), formerly tick/rss and Tideline

"Everything you follow, in one feed." One feed for websites, YouTube, Reddit, podcasts, Google News topics, Bluesky and Mastodon. No account, no tracking; data stays on the device. Do not promise "no ads" anywhere (decided 7 Nov 2026: ads may be part of the business model).

Brand: one orange, #d9480f (`--brand-fill`), for every solid fill in every theme: logo tile, wordmark "Feed", app icon, badges, counts, buttons. `--brand` (#ff8a4c in dark mode) is only for small orange text/lines that must stay readable on dark backgrounds. Android's status/navigation bars take the page background (`YFNative.setBars`), never orange. Wordmark in Bricolage Grotesque 800. Icon: Feed Check (two lines and a tick on an orange rounded square).

Everything lives in `index.html`, served by GitHub Pages at https://jgspl-dev.github.io/Tideline/ now at https://yourfeed.appsforus.co.uk (CNAME file; DNS-only CNAME yourfeed → jgspl-dev.github.io on Cloudflare). The same file is the Android app (`app/`, Capacitor 7, app ID `uk.co.appsforus.yourfeed`).

## Privacy and security rules (agreed Nov 2026)
- Only two kinds of network route: the publisher itself (direct from the device) and our own **YourFeed service** (`service/worker.js`). Never add third-party relays, readers or feed services (removed: allorigins, codetabs, whateverorigin, corsproxy.io, cors.lol, rss2json, Feedly, Jina).
- The service never relays web pages: feeds (validated), allowlisted JSON APIs, or extracted facts only. Sandbox CSP + nosniff on every reply, 5 MB cap, public-address check, CORS limited to our origins, per-IP limits. Its address: `SERVICE_DEFAULT` in index.html (empty until deployed) or Settings → YourFeed service (`yf.service`).
- The service keeps a shared store: edge cache per location plus KV (`YF_CACHE`, namespace yourfeed-cache) for YouTube API results (30 min fresh, written only on change or every 6 h, served stale if the API fails), channel lookups (30 days), searches (1 day), found feeds (7 days). The app asks the service first for YouTube lookups, search and videos (route `ytapi`, then the phone reads YouTube's feed, uploads feed, Videos page). YouTube WebSub push: `ensurePush` subscribes channels at pubsubhubbub.appspot.com (secret derived from YT_API_KEY), `/websub/youtube` verifies and takes HMAC-signed deliveries into KV; while pushing, API freshness is 6 h.
- In the app, feeds are fetched with If-None-Match / If-Modified-Since (`feed.http` per URL); 304 = unchanged. Not until one full read has picked up the feed's artwork (`iconParsed`).
- The app fetches directly (`IS_APP`, CapacitorHttp) and only falls back to the service. The website needs the service for most feeds.
- No third-party loads at startup: fonts self-hosted in `fonts/`, no CDN scripts.
- Android release builds are signed with the private key in Actions secrets `ANDROID_KEYSTORE_B64` / `ANDROID_KEYSTORE_PASSWORD` (alias `yourfeed`). Never commit a keystore. HTTPS only (no cleartext), WebView debugging off.
- Saved posts, folders and sources are local only; export/import via OPML (Settings → Your sources).
- Private (paid) feeds: Patreon, Supercast, Substack etc. give a personal link with an access code. `isPrivateUrl` spots them (secret query params, user:pass@, /private/, long random path segments on paid-podcast hosts; `f.private` set when added). They are fetched only straight from the device: `viaService` refuses any private address, `loadOneFeed` skips the service route, no `healFeed`, added exactly as pasted (no lookups). On the website they show "Private: updates in the YourFeed app" and never count as trouble. Links are blanked with `redactUrl` in Source health and its shared report; export leaves them out unless "Include private feeds" is ticked; Share never sends a private episode's audio link. Padlock (`lockEl`) in the menu and Source health.

## How it works
- Fetch layer: `feedDirect`, `feedViaService`, `fetchFeedText`, `getJSON` (direct then service `/json`), `pageDirect` (app only), `discoverFeed`, `findChannel`. `loadOneFeed` records each route's answer in `feed.routes` (shown in the source's edit form with Check now). Reddit: in the app, one `/new/.rss` request from the phone, spaced 1.1 s apart, browser user agent.
- Each feed has its own schedule (`everyMin`, `nextCheck`, `isDue`): feed ttl / sy:update hints, else 15 min (podcasts 60), clamped 10 min–6 h; failures back off 5→60 min.
- Duplicates: within a feed, a story that comes back under a new address with the same headline (`storyKey`: title minus Google News's " - Publisher", letters/digits, 20+ chars; not audio/video) keeps its first id, and a story's date never moves later (live blogs / re-dated news don't jump back to the top) in `mergeHistory`. Across feeds, `dupeIds` hides the same article from a second source (same `linkKey`, i.e. address minus tracking params/www/#, or same `storyKey`), preferring the publisher's own feed over Google News, then the first seen; not applied when viewing one feed; new counts skip them.
- Seen, not read: a card counts as seen once it is ≥60% on screen (or fills half the screen) for 2 s (`lookObs` IntersectionObserver, `watchLook` in `cardEl`, `markLooked`, `state.looked` / `yf.looked`, last 6000; not in Saved). "New" counts = not seen and not tapped (`isNew`); one-off migration `yf.lookedMig2` starts seen from the tapped (read) set only (the first migration, which marked everything older than the last refresh as seen, made Hide seen empty the feed). Hide seen filters against `state.lookSnap`, re-taken only on filter/source change (`setView`, `selectFeed`), Refresh, or returning after 10+ min, so cards never vanish while scrolling. Tapped = read (faded card, `tl.read`) is kept separately.
- Podcast episodes without their own picture use the show artwork (`f.icon`) on cards, mini player and lock screen.
- News sitemaps: a site with no feed is read from its news sitemap (`isNewsSitemap`, `parseFeed` `urlset` branch: `<loc>`, `news:title`/`news:publication_date`, `image:loc`, title from the URL slug if needed). `#only=/path/` on the address keeps one section (fragment never sent). `findNewsSitemap(origin)` (app only, straight from the site): robots.txt `Sitemap:` lines with news/google, then `NEWS_SITEMAP_GUESSES`; a sitemap index → its newest news child. `discoverFeed` tries it after RSS. The service accepts news sitemaps as feeds (worker `looksLikeFeed`). Settings → Service → Find news sitemaps (`#smCheck`) reports which Google-News-routed directory sites have one, to switch them over (fewer calls to Google, real links and pictures). Nov 2026 run: 56 sites switched (e.g. Bloomberg, The Times, CNN, The Athletic `#only=/athletic/`, Autocar, Top Gear, Yahoo Finance); sources a person already added through Google News move to the new route automatically when their name matches a non-Google directory entry.
- Google News topics (not `site:` feeds) keep English headlines only (`looksEnglish` in `parseFeed`: other scripts out; Latin-script headlines judged by everyday words, `EN_WORDS` vs `OTHER_WORDS`, plus accent share). All Google News addresses already use the English editions (UK, or US for Worldwide).
- Crash guard: `fetchFeedNow` records sources being loaded in `yf.inflight` (only while the app is on screen). If the app dies mid-load, `crashCheck()` at start counts a crash against each (`f.crashes`); a source loading during two crashes gets `f.crashPaused` (skipped by `isDue`, plain message, "Check" in Source health unpauses). Feeds over 8 MB, compressed (gzip) responses, and sitemaps beyond 400 entries are refused/trimmed (added after 0.2.40 crashed a few seconds after opening).
- History: 7 days per feed, at least the 20 newest (`KEEP_DAYS`, `MIN_PER_FEED`, max age 180 days).
- Top bar: wordmark with "by Apps For Us"; Saved button and a play button (`#nowBtn`, always shown, orange while playing) on the right: opens the full-screen player for the loaded episode, else the last started one (`startedEpisodes()[0]`, ready to continue), else switches to the Audio feed. Under it: Refresh (`#refresh`, spins while checking) with the health light in its middle (`#healthDot`), then an (i) box (green; orange (!) when sources need attention) that opens a summary pop-up (`#statusPop`: "All N sources working · next check…", or the problem sources in plain words plus "Open Source health"); `paintHealth`, `toggleStatusPop`. Then a pill for what's showing (type · category/feed, tap to clear) and the Filter button. The content-type tabs (`#chips`) are hidden: types live in the filter box. Filter box (`renderFilterBox`): SHOW (Everything, Articles, Topics, Videos, Audio, Conversations with new counts; Topics = Google News topic feeds, `typeOf` "topics"; plus Hide seen: `view.unread`, filtered against the snapshot `state.lookSnap`), CATEGORY (dropdown of the fixed categories with source counts, "Your own" folders, Unsorted; "Your own categories" lets you rename one or move its sources into a fixed category or sort them automatically, which removes it), FEED (one feed), FROM (default Week, `yf.fromWeek` migration), SORT, STACK (design.stack). Saved is a mode (`view.saved`) using the same filter; saved audio is a queue (first saved, first played; setting `yf.podQueue`). First-visit explainer per type (`TYPE_HELP`, `yf.tabHelp`). Back-to-top button.
- Podcast feed = at least 60% of posts have audio (`isPodcastFeed`); a website with the odd episode stays in Articles. Social sources added from search get `kind: "social"`. Names are tidied (`cleanTitle`: r/name, bs/Name; a feed in `DIRECTORY` takes our name for it; other website names lose filler via `tidySiteName`/`FILLER`, e.g. "IGN All" → IGN, "Latest updates - X" → X, "X | RSS Feed" → X; one-off rename of existing website sources `yf.tidyNames`). Threads accounts and accounts with under 10 posts are left out of search.
- Default look: Magazine, large images. Reddit images: full size from the `[link]` in Reddit's RSS, `preview.redd.it` → `i.redd.it`.
- Errors stay quiet: a source is flagged ("Needs attention", status line) only when `isTroubled` (failing for 24 h, or a permanent error twice). Flags use `plainTrouble` (one sentence) with Check/Remove/Dismiss icons. Website feeds that stop being feeds are re-found from the site's home page (`healFeed`, once a day). All technical detail lives in Settings → Source health (`openReport`, per-source Details, Share/Save as file/Copy).
- Podcast downloads (app only, `CAN_DOWNLOAD`: @capacitor/file-transfer `FileTransfer.downloadFile` to a Filesystem URI, Filesystem.downloadFile as fallback; failures show the real reason): files in app storage (`DATA/episodes/`), list in `yf.downloads`; downloading also saves the episode; played downloads are deleted (`yf.dlAutoDelete`), Wi-Fi only by default (`yf.dlWifi`, via navigator.connection); playback uses the local file (`dlSrc`, convertFileSrc) and falls back to streaming. DOWNLOADED flag; Settings → Podcasts shows count/MB and Delete all. Every episode post has a footer: Read description · Website ↗ (`podFoot`); Download is an icon next to Save and Share (`downloadBtn(it, true)`: arrow → % → green tick). Episode pictures carry a play/pause button where videos have their badge (`.podplay`, kept in step by `syncPod`). When an episode ends with nothing queued after it, it is cleared away (`stopPod`, full-screen player closed, mini player hidden, "Finished" toast); with the saved queue on, the next one plays (and the open player switches to it). Continue listening lists every started episode, newest on show, the rest behind "N more started"; ✕ forgets one.
- No accent colour setting (removed Nov 2026): `design.accent` is always "orange".
- Episodes open as a full-screen player sized to fit one phone screen without scrolling (artwork `min(66vw,300px,36vh)`, title clamped to 2 lines, 64 px play button; Download is a `.pp-act.pp-dl` icon + label, painted by `paintDl`) (`openPlayer`, the article page with `.is-pod`): big artwork (episode image, else show artwork, else letter), show, title, date · length, progress bar, back 15 / play / forward 30 with speed at the side, then Save / Share / Download / Website buttons and folded Episode notes.
- Podcasts: Listen / Continue (time left) / Played tags (`podStatus`, `yf.played`, `yf.podDur`, `yf.podLast`); Continue listening at the top of Audio. Headphone next/previous = skip (native: `onMediaButtonEvent` in the forked plugin; website: Media Session next/previous).
- Videos play in YourFeed by default (`yf.videoInApp`); in the app `app/native/MainActivity.java` (copied in by the build) lets them go full screen in landscape.
- Bluesky & Mastodon search sorts mirrors (`sortSocial`, `directFor`): web.brid.gy website bridges and feed-bot copies (bot flag/label or "unofficial/automated/RSS…" bios about news/headlines) become the publisher itself (our `DIRECTORY` entry, else its website) or are dropped; Bluesky accounts bridged to the fediverse (bsky.brid.gy) become the Bluesky account; fediverse accounts bridged to Bluesky (*.ap.brid.gy) are left to Mastodon search. Flipboard is kept (curated magazines) and filed as articles (`kind: "flipboard"` → feed.kind "web" → Websites). Lemmy communities → their own feed `/feeds/c/NAME.xml?sort=New` (Conversations); PeerTube channels → `/feeds/videos.xml?videoChannelName=` (feed.kind "video" → Videos); WordPress blogs on the fediverse → the blog's feed (Articles).
- Reddit search: `searchRedditList` asks Reddit's JSON search and its RSS version (`searchRedditRss`, /subreddits/search.rss, read like a feed) at the same time and merges them, because the JSON one is often refused to apps and cloud servers; the exact r/name (`redditExact`) still comes first.
- Search: website search is our own `DIRECTORY` only (no outside search service sees queries; ~670 entries, at least 20 per category; Google News is only a route: a site with no feed we know is a Google News `site:` feed shown and named as the site itself (`siteOf`; no "via Google" anywhere, one-off rename `yf.noViaGoogle`), plus a few Google News topic feeds shown as "News topic"; covering every `INTERESTS` category plus UK regional news (Reach plc `/?service=rss`), international outlets and newsletters (Substack `/feed`, Ghost `/rss/`); publisher feeds on known patterns: Hearst `/rss/all.xml/`, Condé Nast `/feed/rss`, Vox/NY Mag `/rss/index.xml`, Future plc `/feeds/all`, WordPress `/feed/`), fuzzy matching (`dirMatch`) on name, site and tags. Publishers with many section feeds (`PUBLISHERS`: The Guardian, BBC News, BBC Sport, Sky News, Sky Sports, ESPN, The Independent, Daily Mail, The Telegraph) show as one result (`groupPublishers`) only when the search names the publisher ("guardian", "bbc sport"): its main feed plus a "Choose sections (N)" toggle with a chip per section (`resultEl` → `.rsec-chips`). A subject search ("football", "food") lists every matching section as its own result, with publishers interleaved (each publisher's first match, then each one's second…) so one publisher doesn't fill the top. `NO_FEED` is now empty: AP, Reuters, Bloomberg, The Athletic, The Times, Nintendo, BBC Food and The Irish Times are ordinary directory entries via Google News. `dirMatch` matches words at word starts (and squashed names by prefix), so "ipl" doesn't find Kiplinger. If nothing matches, the subject is offered as a Google News topic so Websites never comes back empty. New directory feeds were added from known URL patterns without a live check (Nov 2026): Settings → Service → Check search list (`#dirCheck`) loads every `DIRECTORY` feed once from the device (4 at a time, Google News one at a time 0.9 s apart), marks fail / moved (site discovery found another feed) / empty / stale (nothing in 30 days), and shares the list (`dirReport`) so they can be fixed.
- Search pills match the feed types (`PILLS`: All · Articles · Topics · Videos · Audio · Conversations); each gathers results from the searches that can produce it (`from`) and keeps only its own (`pillOf`: news/News topic → Topics, YouTube/PeerTube → Videos, Reddit/Lemmy/Bluesky/Mastodon → Conversations, podcasts → Audio, the rest incl. Flipboard → Articles); old platform pill choices fall back to All. Each result keeps its source label. PeerTube channels describing themselves as mirrors/re-uploads/archives of YouTube are dropped.
- Community list (agreed 10 Nov 2026, minimal data): when a pasted website works, `shareSite` sends only its domain (`siteDomain`, e.g. bbcgoodfood.com) to the service `/community/add`; never private feeds, social/YouTube/Reddit/podcasts/Google News, or sites already in `DIRECTORY`; setting Settings → Sources → Help improve search (`yf.shareSites`, on by default) and a Policies line. The service checks the site has a feed the first time, counts different people by a 10-character one-way code of connection + month (kept only until approval, then cleared), and lists the domain in `cm:index` once `COMMUNITY_MIN` (3 for testing; raise to ~10 at launch, or set env `COMMUNITY_MIN`) have added it. Phones fetch `/community/list` at most once a day (`loadCommunity`, `yf.community`) and search it locally ("Added by other YourFeed users"); adding goes through normal discovery. No user counts exist, so the threshold is a fixed number, not a percentage (could be set from Play Console active installs).
- Menu: search box, then the search-type chips, then a three-line hint (Paste a link…, Search for…, Paid subscription?…; placeholder "Paste a link or search"). Organise by Category (folders) or Type (`sourceType`/`SOURCE_TYPES`: Articles, Topics, Videos, Audio, Conversations; old "platform" setting migrates to "type"), channels A–Z (no Everything row). Sources with no folder are "Uncategorised" (`UNSORTED`). The edit form's Folder list: Categories (all of `INTERESTS`), Your folders (custom), Uncategorised, + New folder….
- What you can/can't follow: `SUPPORT_YES` / `SUPPORT_NO` (short reason each), rendered by `supportInfo()`. Shown once under "No sources yet" in the menu with Got it (`yf.supportSeen`, also set once any source exists), then only in Settings → FAQs (`#sf-faq`, `renderFaqs`: the same lists plus `FAQS` questions).
- Settings sections are folded `<details class="setfold">` (`#sf-look`, `#sf-content`, `#sf-sources`, `#sf-svc`, `#sf-faq`, `#sf-pol`), all closed on open, only one open at a time (opening one folds the rest); links into Settings (Open Source health, Import a list) unfold Sources. Sections: Look · Content (Videos and links, Podcasts/downloads) · Sources (Source health + Needs attention, Import and export) · Service (YourFeed service, connection check) · FAQs · Policies (plain-words privacy points, YouTube Terms + Google Privacy links). The app version/build line sits at the very bottom, outside every section.
- Source icons instead of coloured dots (`srcIcon`/`iconFor`, in cards, stacks, menu and reader): the feed's own artwork/logo (`parseFeed` → `f.icon`, itunes:image / RSS image / Atom icon; Reddit's generic logo ignored), else a one-off lookup (`fetchSourceIcon`: YouTube avatar from /youtube/latest (`avatar`, channels.list once per channel) or the service's channel lookup, subreddit icon via about.json, Bluesky avatar), websites always try the tab icon first (/favicon.ico, then /apple-touch-icon.png, then the feed logo); otherwise the first letter on the source's colour. Loaded straight from the publisher; nothing for Google News topics or extra lookups for private feeds.
- Cards: one stretched link per card (`.cardlink`). Flags (`flagsEl`: WATCH + clock length, LISTEN + minutes, READ, COMMENT; grey, orange only for Continue) and Save/Share: Magazine shows pictures uncropped (`.shaped`, very tall ones capped at 78vh) with the age in a pill top left and Save/Share in a pill top right of the picture (top line if no picture), List puts flags in a strip at the bottom of the text with Save/Share at its right end, beside the picture; cards without a picture keep them in the same place (`--tw`). Lengths: YouTube `dur` from the service (`/youtube/latest`, videos.list only for new videos), podcasts from itunes:duration. Saved posts in `yf.saved`.
- YouTube items use one address (`/watch?v=ID`) whichever route they came from, so a Short (linked `/shorts/ID` in YouTube's feed) can't appear twice; `short: true` is kept, shown as a SHORT flag, and Shorts play in an upright 9:16 frame in the card.
- Keyboard (app): Android 15 draws edge to edge, so MainActivity pads the content view by the keyboard height (minus the nav bar) to shrink the page; the edit form then lines the keyboard up above "Health".
- Full screen (app): MainActivity turns to landscape unless the video is a Short (`YFNative.setRotateFull(false)`), wraps the player in `DragToClose` (drag down to close), and calls `yfVideoEnter`/`yfVideoExit` in the page, which pauses the video (YouTube iframe API, `enablejsapi=1`) and scrolls the card back to where it was. The website does the same on `fullscreenchange`.
- Videos tab has a Videos | Shorts switch (`view.vkind`, `videoSwitch`; Shorts = `isShortItem`: `short === true` only, set by YouTube's /shorts/ links or the service's `shortCheck`, never by length) and Shorts show as a two-column grid of upright tiles (`.shortgrid`, stacks off). Settings → Hide YouTube Shorts (`yf.hideShorts`) removes them everywhere.
- One thing plays at a time: YouTube players are watched (`watchVideo`, iframe API "listening" + onStateChange); a video starting pauses the podcast and other videos, a podcast starting pauses all videos (`pauseAllVideos`), and in-feed videos pause when scrolled mostly out of view (`vidSeen` IntersectionObserver).
- No background play for YouTube: YouTube's API rules forbid it. Podcasts keep background play.
- Onboarding: welcome screen when there are no sources, interest picker → folders (`INTERESTS`), spotlight tour (`TOUR`).
- Categories: a fixed list (`INTERESTS`, 26; Literature & Arts added Nov 2026). A `DIRECTORY` feed is filed by its first tag (`tagCategory`, `TAG_CAT` aliases like games→Gaming, f1→Motorsport), so keep the first tag of every directory entry a category word. Broad ones (`BROAD`: Sport, Lifestyle, Business) count for less and give way to a clear match in their `FAMILY` (Sky Sports Golf → Golf). `categorise` scores the source's name/address (strong, 4), our directory tags (+3, so "The Guardian – Cricket" lands in Cricket; "guardian" is no longer a News word) and its recent posts (weak); new sources go straight into the winning category (folder made if needed) with an "Added to X · Change" note (cleared when the menu closes), no question. Sources with no folder are sorted on their first successful check (`autoCat`); a folder picked by hand (`folderSet`) is never changed.
- "Quiet" (nothing new for 3× its usual gap) never applies to YouTube channels that load: they count as working.
- Needs attention lives in Settings under Source health (`renderAttention`, a collapsible bar; tapping a warning in the status line opens it). Rows: icon buttons Check / Remove (tap twice) / Dismiss (`f.dismissed`, cleared when the source works again; the status count stays honest).
- Podcasts: shared player `pod`, mini player, Media Session; in the app a forked media-session plugin (`app/plugins/media-session`) runs a foreground service, with back/forward as Android 13+ system media controls. Stall guard `checkPod`.
- YouTube is touchy about bursts from one connection (it blocks it with 404/500 for hours): requests go one at a time 1.5 s apart (app fetch wrapper), channels are checked every 30 min with a per-source jitter, at most 10 per refresh round, and `ytRefused`/`ytCooling` pause all YouTube requests 30 min→6 h after 4 refusals in a row. Fallbacks (uploads-playlist feed, channel Videos page) only for one-off failures. Imports by name look up one channel at a time.
- Android back button (`goBack`): closes the open layer, then returns to Everything, then minimises the app.
- Storage keys keep the old `tl.` prefix (new ones use `yf.`); keep them.

## When checking or adding a publisher
1. Image sharpness: add `IMAGE_RULES` for bigger images, always keeping the feed's own image as a fallback.
2. Feed discovery: site address, feed link and (YouTube) @handle, channel and video links must all work.
3. Story count vs what the feed holds.
4. Links that push visitors to an app.

## Testing
- The sandbox can't reach outside sites: test with Playwright against mocked routes (direct publisher URLs with CORS headers, or a mocked service). `service/worker.js` can be unit-tested in Node with a stubbed `fetch`.
- Android builds run in GitHub Actions (`.github/workflows/android.yml`) and publish the `test-build` release (`yourfeed.apk`). Settings shows the build number. Builds are manual only (workflow_dispatch): do not trigger one until Josh asks; batch small changes into one release.
